# CRAFTNIVO — Client Website Delivery Playbook

Status: internal operating procedure. No client site is considered delivered until every required check is complete.

## 1. Inquiry and scope
- Receive the client's project description through an approved business channel. Do not claim the current website's copy-only form submits inquiries.
- Confirm business name, preferred language, pages, features, reference sites, brand assets, content, contact details, domain preference, and deadline.
- Agree in writing on price in AED, deliverables, revision rounds, milestones, timeline, paid integrations, domain/hosting renewals, maintenance, and ownership.
- Obtain explicit client approval before purchasing a domain, paid hosting, subscriptions, or enabling a payment provider.

## 2. Project and content
- Create a separate private project/repository per client, never use the public CRAFTNIVO demo as the client's live source of truth.
- Request only required assets and information; do not commit customer contact information, credentials, API keys, or private files to a public repository.
- Implement responsive layouts, accessible navigation, content, forms, and requested functionality. Use licensed or client-provided images.
- Demo carts and demo forms are not production commerce or intake systems.

## 3. Preview and acceptance
- Publish a staging/preview link clearly marked as a preview; avoid exposing client-sensitive content.
- Test desktop and mobile layouts, Arabic/English and RTL if ordered, internal links, form delivery, images, navigation, performance, and accessibility basics.
- Request written approval of the final preview and track the agreed revision rounds.

## 4. Production launch
- Prefer domain and hosting accounts owned by the client; obtain temporary delegated access rather than passwords where possible.
- Back up the approved build and configure production hosting, DNS, HTTPS, custom domain, and any agreed integrations.
- For production stores, use an approved payment provider and verify checkout, orders, receipts, refunds/terms, and security before announcing that purchases are live.
- Verify the real domain loads with HTTPS, including on mobile, and check all business contact methods.

## 5. Final handover
Provide the client with:
1. Live website URL and date of launch.
2. Domain registrar and hosting provider details, ownership and renewal responsibilities.
3. Admin/editor access or a secure transfer of ownership; never send passwords in public messages or source code.
4. Source files/repository access and backup as specified in the contract.
5. Simple content-editing instructions, third-party integration inventory, and support contact.
6. Acceptance confirmation, outstanding items, and maintenance/warranty terms.

## 6. Post-launch
- Confirm successful handover and collect final payment according to the agreed contract.
- Remove temporary access not needed for support.
- Schedule optional maintenance only if the client opts in; never imply indefinite free support.

## Release checklist
- [ ] Written scope and payment terms approved
- [ ] Client assets and usage rights confirmed
- [ ] Responsive and functional testing passed
- [ ] Contact form tested end-to-end with real recipient
- [ ] Domain, DNS and HTTPS checked
- [ ] Real payment checkout tested, if included
- [ ] Client approved production preview
- [ ] Backup and source handover completed
- [ ] Client controls domain and hosting, or alternative ownership explicitly documented
- [ ] Credentials transferred securely
- [ ] Support/maintenance and renewals explained
- [ ] Client acknowledged handover

## Current CRAFTNIVO platform blockers
- No verified business inbox or WhatsApp destination is configured for actual inquiries.
- The current inquiry form only copies/downloads a summary; it does not transmit requests.
- The store and cafe are demos; the demo store does not accept real payments.
- No customer portal or automated deployment/hosting integration is configured.
